# Переезд прототипа на GitHub Pages

Сайт спроектирован как **чистая статика**: ни сервера, ни БД. Все данные лежат в
`public/data/*.json`, картинки — в `public/img/posts/`. Ровно это и умеет GitHub Pages.

## Схема работы после переезда

```
GitHub Actions (каждые 30–60 мин, cron)
  → скрипт вызывает VK API (wall.get) с сервисным токеном из Secrets
  → перегенерирует public/data/*.json и скачивает свежие фото
  → git commit + push
  → next build → out/
  → GitHub Pages раздаёт статику
```

## Шаги (один раз)

1. **Создайте репозиторий на GitHub и загрузите туда файлы сайта** (список
   файлов — в конце этого документа, ниже). Конфиг уже готов: при обычной
   сборке сайт собирается для предпросмотра, а workflow на GitHub сам включает
   статический экспорт (`NEXT_EXPORT=1` → `output: "export"` в `next.config.ts`).

2. **basePath не нужен вручную.** Workflow сам определяет имя репозитория:
   для `username.github.io/repo` префикс `/repo` подставляется в сборку и
   в клиентский код (`NEXT_PUBLIC_BASE_PATH`), панель /admin тоже определяет
   его автоматически из адреса страницы. Если сайт живёт на личной странице
   `username.github.io` — префикс пустой, всё тоже работает без настроек.
   Важно: в `src/lib/feed.ts` чтение файлов идёт из `process.cwd()/public` —
   при сборке это работает без изменений; все fetch и картинки сайта проходят
   через хелпер `withBase()` из `src/lib/base-path.ts`, поэтому подкаталог
   поддержан из коробки.

3. **Установить зависимости и собрать локально для проверки** (необязательно):
   `bun install && NEXT_EXPORT=1 bun next build` → появится папка `out/`.

4. **Workflow.** Файл уже лежит по нужному пути: `.github/workflows/github-pages.yml`.
   В настройках репозитория → Pages → Source: **GitHub Actions**.

5. **Секрет для VK API.** Settings → Secrets and variables → Actions →
   новый секрет `VK_SERVICE_TOKEN`.

## Как получить сервисный токен ВК (2 минуты)

1. Откройте `vk.com/apps?act=manage` → **Создать приложение**.
2. Название любое (например, «Лента сайта»), тип — **Standalone**.
3. В настройках созданного приложения появится **«Сервисный токен доступа»** — это он.
4. Вставьте его в секрет `VK_SERVICE_TOKEN`. Токен остаётся на стороне GitHub,
   в коде и в самом сайте его нет.

Публичные посты открытого сообщества читаются методом `wall.get`
(`v=5.199`, параметр `domain=короткое_имя_группы`) без дополнительного доступа.

## Формат данных (контракт между скриптом и сайтом)

| Файл | Что это | Кто заполняет |
| --- | --- | --- |
| `public/data/posts/page-N.json` | чанки ленты по 6 постов | скрипт сборки |
| `public/data/top.json` | топ-5 по вовлечённости (лайки + 2×репосты + 3×комментарии) | скрипт сборки |
| `public/data/promo.json` | промо-слот (ваш «закреп») — правите руками или из формы | вы |
| `public/data/recommend.json` | блок «Рекомендуем» — второй платный слот | вы |
| `public/data/group.json` | шапка: название, участники, ссылка ВК | скрипт сборки |

Каждый пост: `id, date (ISO), text, photos[], likes, reposts, comments, views,
hashtags[], vkUrl, related[{id,title}]`, плюс необязательный `pinned: true` —
такой пост автоматически ставится первым в ленту с бейджем «Закреплено».
В проде это поле берётся прямо из VK API: у закреплённого в группе поста
`wall.get` возвращает `is_pinned: true`, поэтому достаточно нажать «Закрепить»
в самой группе ВК — сайт подхватит при следующей сборке. Прототип уже выдаёт
ровно эту структуру — в `scripts/gen-demo-data.mjs` замените демо-массив
на ответы `wall.get`, и всё.

## Продажа рекламы

- Промо-карточка и «Рекомендуем» помечены бейджем «Реклама» с полем ЕРИД —
  при реальном размещении токен получают через ОРД (есть бесплатные) и вписывают
  в `promo.json` / `recommend.json`.
- Кликабельность слотов измеряется Яндекс Метрикой (цели по кликам) — она
  работает на статике, счётчик добавляется одним `<script>` в `layout.tsx`.

## Панель рекламодателя (`/admin`)

Страница `/admin` (в футере — ссылка «вход для редактора», закрыта от индексации
мета-тегом и robots.txt) — это форма загрузки рекламного поста без права
что-либо править в коде.

**Защита панели (два уровня):**

1. *Пароль устройства.* При первом открытии панель просит придумать пароль —
   он сохраняется (SHA-256 с солью) только в localStorage этого браузера
   и не попадает в публичный репозиторий. Кнопка «Заблокировать» в шапке
   закрывает панель до ввода пароля; разблокировка живёт до закрытия браузера
   (sessionStorage). Сброс пароля заодно стирает сохранённый токен.
2. *Токен GitHub.* Настоящая защита сайта — ваш личный PAT: без него ни один
   посетитель не может закоммитить изменения. Форма без токена лишь
   предпросмотр и скачивание файлов к себе на компьютер.

**Как пользоваться (3 минуты):**

1. Заполните поля: слот («Промо-блок» или «Рекомендуем»), рекламодатель,
   заголовок, текст, кнопку, ссылку и ЕРИД. Предпросмотр слева обновляется сразу.
2. Загрузите картинку — она сожмётся до 1200 px по ширине (JPG, ~200 КБ).
   Либо включите переключатель «Файл уже в репозитории» и укажите путь.
3. В правой колонке один раз заполните `владелец/репозиторий`, ветку и
   `basePath` (тот же, что в `next.config.ts`). Вставьте личный токен GitHub
   (PAT) с правом **Contents: Read and write** —
   создать: `github.com/settings/tokens`. Токен хранится **только в вашем
   браузере** (localStorage), в код сайта не попадает.
4. Нажмите «Опубликовать рекламный пост». Панель сама закоммитит
   `public/img/promo/<slug>-<hash>.jpg` и `public/data/promo.json`
   (или `recommend.json`) через GitHub Contents API.
5. Через 1–3 минуты Actions пересоберёт Pages — слот обновлён.

**Без токена:** кнопки «JSON-файл» и «Картинка» скачивают готовые файлы —
их можно закоммитить в репозиторий руками, результат тот же.

Черновик и настройки панели автосохраняются в браузере. Токен — личный,
передавать его третьим лицам (в т.ч. рекламодателям) не нужно: контент им
можно присылать текстом, а в панель вносить самостоятельно.

## Подключение группы ВК

Сайт привязан к группе **vk.ru/online_tyumen72** («Бесплатные объявления
Тюмени. | Реклама | Работа»). Название, описание и число участников подтянулись
автоматически со страницы группы; посты ВК отдаёт только через API с токеном,
поэтому для ленты нужен один раз созданный токен.

**Как получить сервисный токен (5 минут):**

1. Откройте `https://vk.com/editapp?create=` и создайте standalone-приложение
   (любое название, тип «Standalone»).
2. В настройках приложения скопируйте **сервисный токен доступа** (Service token).
3. В своём репозитории: Settings → Secrets and variables → Actions →
   New repository secret → имя `VK_SERVICE_TOKEN`, значение — токен.

Никаких прав доступа у сервисного токена запрашивать не нужно: стена публичной
группы читается им без разрешений. Токен лежит только в секретах GitHub,
в код сайта не попадает.

**Что делает скрипт `scripts/fetch-vk.mjs`** (запускается в Actions перед
каждой сборкой и может быть запущен локально):

```bash
VK_SERVICE_TOKEN=ваш-токен node scripts/fetch-vk.mjs
```

1. `public/data/group.json` — название, описание, участники, ссылка
   (без токена это тоже работает: данные читаются с публичной страницы группы).
2. `public/data/posts/page-*.json` — последние 60 постов стены: текст, фото
   (до 1280 px), лайки, репосты, комментарии, просмотры, `is_pinned`.
3. `public/data/top.json` — «Топ недели» пересчитывается автоматически
   (лайки + репосты × 2 + комментарии × 3).
4. `public/data/pinned.json` — если закреп задан в панели, он сохраняется;
   иначе берётся пост, закреплённый в самой группе ВК.
5. Без токена посты не трогаются — пустой запуск не может стереть данные.

## Workflow: github-pages.yml

Готовый файл уже в репозитории: `.github/workflows/github-pages.yml`.
Он запускается при пуше в main, каждые 45 минут по расписанию и вручную
(кнопка Run workflow), и делает одно за другим:

1. `node scripts/fetch-vk.mjs` — обновить посты из ВК (секрет `VK_SERVICE_TOKEN`);
2. сам определяет basePath по имени репозитория (`username.github.io/repo` → `/repo`);
3. `bun next build` со `NEXT_EXPORT=1` — статический экспорт в `out/`;
4. выложить артефакт на GitHub Pages (`deploy-pages@v4`).

Ничего вручную вписывать не нужно — и для корня, и для подкаталога работает
один и тот же workflow.

## Какой файл куда (состав репозитория)

| Путь | Что это |
| --- | --- |
| `src/`, `public/`, `package.json`, `bun.lock`, конфиги (`next.config.ts`, `tsconfig.json`, `postcss.config.mjs`, `tailwind.config.ts`, `components.json`) | сам сайт |
| `.github/workflows/github-pages.yml` | сборка и публикация на Pages + автоподтяжка ВК |
| `scripts/fetch-vk.mjs` | выгрузка постов из группы ВК в `public/data/` |
| `README.md` | этот документ |

Папки `node_modules/`, `.next/`, `out/` в репозиторий не попадают — их
пересоздаёт сборка (`.gitignore` уже настроен).
